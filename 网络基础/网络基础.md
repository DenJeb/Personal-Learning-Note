## 1. 客户端（Client）和服务器（Server）

连接到互联网的计算机被称为**客户端**和**服务器**。

![image.png](<图片和附件/image 1.png>)

- 客户端是指网络用户连接到互联网的设备（例如，连接到 Wi-Fi 的计算机或连接到移动网络的手机），以及这些设备上可用的网络访问软件（例如 Chrome）。
- 服务器是储存网页、网站或应用程序的计算机。当客户端想要访问某个网页时，网页代码的副本会从服务器下载到客户端计算机上，然后由浏览器渲染并显示给用户。

### 1.1 实现客户端和服务器的数据传输，需要以下条件

- **互联网连接**：使你能够在互联网上发送和接收数据，它就像连接你家和商店的街道。
- **TCP/IP**：TCP（Transmission Control Protocol，传输控制协议）和 IP（Internet Protocol，互联网协议）是两个最核心的协议，TCP/IP 通常泛指整个互联网通信协议族。它就像把商品运回家的运输机制，例如汽车或自行车。
- **域名系统（DNS）**：URL 中的域名需要通过 DNS 解析为 IP 地址，才能用于网络通信。DNS 就像网站的地址簿：当你在浏览器中输入网址时，浏览器会先查询 DNS，找到网站的 IP 地址（服务器的实际地址），然后才能访问该网站——就像去商店之前先查询它的地址一样。
- **超文本传输协议（HTTP）**：HTTP 是一种应用层协议，它定义了一种供客户端和服务器相互通信的语言，就像你订购商品时使用的语言一样。

## 2. 端口

**端口号范围 0~65535，一共 65536 个端口**

- **IP 地址负责找到设备，端口号负责找到服务**

> ❓ 为什么需要端口？一台电脑可以同时运行多个程序，需要用端口号来区分不同的服务。

### 2.1 端口分类

1. **知名端口（0~1023）**：通常分配给常见的网络基础服务。如：HTTP 使用 80 端口，HTTPS 使用 443 端口，发邮件使用 25 端口，远程登录服务器（SSH）使用 22 端口。
2. **注册端口（1024~49151）**：通常用于一些特定软件和网络服务/普通应用程序。如：MySQL 使用 3306 端口，Redis 使用 6379 端口。
3. **动态端口/私有端口（49152~65535）**：主要用于临时网络连接。如：主动连接访问网站时，系统为这次临时连接分配端口，用完后释放。

> ⚠️ 安全问题：端口对应的服务存在漏洞或配置不当，可能成为攻击者的入侵对象。

### 2.2 端口冲突

电脑上已经有一个程序占用此端口，而另一个程序也需要使用这个端口。

解决方法：

- 修改配置，更换端口号
- 停止占用该端口的进程

**如何查看端口占用？**

- **Windows：**

```PowerShell
netstat -ano
```

- **Linux/Mac：**

```bash
lsof -i :端口号
# 或者
netstat -tuln
```

## 3. TCP 和 UDP

网络通信按分层模型组织（TCP/IP 四层模型）：

```Plain Text
应用层
  ↓
传输层
  ↓
网络层
  ↓
网络接口层
```

TCP 和 UDP 都属于传输层，首部都包含端口信息。

![image.png](<图片和附件/image 2.png>)

即使不含选项字段，**TCP** 首部最少也要 **20 字节**，**UDP** 首部固定为 **8 字节**。

![image.png](<图片和附件/image 3.png>)

### 3.1 TCP

TCP 不会马上发送数据，而是先进行**三次握手**：`SYN` → `SYN+ACK` → `ACK`，**确认连接**。通信结束后通过**四次挥手**释放连接：`FIN` → `ACK` → `FIN` → `ACK`。

TCP 是面向连接的、可靠的字节流传输协议，通常用于两个端点之间的通信。

![image.png](<图片和附件/image 4.png>)

![image.png](<图片和附件/image 5.png>)

- 传输开销较大，速度相对较慢。额外的开销用于序列号、确认应答号等。

### 3.2 UDP

UDP 直接发送数据，不需要先建立连接。

UDP 是无连接的、不保证可靠传输的报文传输协议，开销较小。

- 传输方式更加轻量化，速度相对较快。但传输稳定性低，不能保证不丢失数据包。

### 3.3 TCP 与 UDP 对比

|          | TCP                    | UDP                               |
|----------|------------------------|-----------------------------------|
| 连接方式 | 面向连接（三次握手）   | 无连接                            |
| 可靠性   | 可靠，保证按序到达     | 不保证可靠，不保证顺序            |
| 传输单位 | 字节流                 | 数据报                            |
| 首部开销 | 最小 20 字节           | 固定 8 字节                       |
| 速度     | 较慢                   | 较快                              |
| 典型应用 | HTTP、SSH、文件传输    | DNS 查询、直播、语音通话、在线游戏 |

## 4. 域名系统（DNS）

URL 是资源的地址，例如 `https://github.com/`；其中的域名 `github.com` 可以通过 DNS 解析为 IP 地址。IP 地址代表了网络上的唯一位置，但不好记忆，这就是域名系统（DNS）诞生的原因。DNS 使用专门的服务器，把你输入的域名（例如 `mozilla.org`）与网站的真实 IP 地址进行匹配。

DNS 查询的大致过程：

1. 先查本地缓存（浏览器缓存、系统 hosts 文件）
2. 缓存未命中，则向 DNS 服务器发起查询
3. DNS 服务器逐级查询，最终从权威服务器得到 IP 并返回

大型网站通常会部署在多个服务器上，以便为世界各地的不同用户高效加载，因此解析出的 IP 地址可能因你的位置而异。

## 5. URL 的组成部分

在浏览器地址栏中输入的是**统一资源定位符（URL，Uniform Resource Locator）**。一个完整的 URL 可以拆成以下几部分：

```Plain Text
https://example.com:443/users?id=123
```

- `https`：协议（Protocol）。HTTPS 是 HTTP 的安全版本，传输过程加密，可以防止数据在传输中被窃取或篡改。现代网站几乎都使用 HTTPS——即使不显式输入，浏览器也会默认使用并自动补全。
- `example.com`：域名（Domain / Host），代表要连接的服务器。域名可以有多级结构，例如 `developer.mozilla.org` 是 `mozilla.org` 的**子域名**。
- `443`：端口（Port）。HTTPS 默认端口是 443，HTTP 默认是 80，通常可以省略。
- `/users`：路径（Path），服务器上资源所在的位置。例如 `https://developer.mozilla.org/en-US/` 中的 `/en-US/` 就是路径。
- `?id=123`：查询参数（Query Parameters），以 `?` 开头，多个参数之间用 `&` 分隔，用于向服务器传递额外信息。

## 6. 数据包

数据在网络中传输时，会被分成多个称为**数据包（Packet）**的小块，每个数据包包含：

- **头部信息（Header）**：包含源/目的 IP 地址、端口、序号等传输控制信息。
- **有效载荷（Payload）**：数据包中实际发送的数据。

数据以小数据包形式发送的主要原因：

- 数据包有时会丢失或损坏，此时客户端只需请求重传丢失的数据包，比重新请求整个文件快得多、也容易得多。
- 数据包可以沿着不同的路径路由，从而尽可能提高传输效率，降低网络变慢的可能性——尤其是许多用户同时请求同一资源时。数据包到达的顺序可能不一致，但客户端可以根据头部信息把它们按正确的顺序组装。

## 7. HTTP

HTTP（HyperText Transfer Protocol）是一种**应用层协议**，用于客户端和服务器之间进行资源交换。

HTTP 采用**客户端-服务器（Client-Server）模型**：客户端发送 **Request（请求）**，服务器返回 **Response（响应）**。

HTTP 最初主要用于获取超文本资源，但现在也广泛用于获取图片、视频、JSON 数据，以及向服务器提交数据，因此是 Web 数据交换的核心协议。

![image.png](<图片和附件/image 6.png>)

### 7.1 HTTP 消息（HTTP Messages）

客户端和服务器通过交换 **HTTP 消息（HTTP Message）** 进行通信：

- 客户端发送 **Request（请求）**
- 服务器返回 **Response（响应）**

```Plain Text
Client
   │
   │ HTTP Request
   ▼
Server
   │
   │ HTTP Response
   ▼
Client
```

![image.png](<图片和附件/image 7.png>)

常见的 HTTP 通信基于：

```Plain Text
HTTP/1.1 → TCP
HTTP/2   → TCP
HTTP/3   → QUIC（基于UDP）
```

HTTPS 并不是另一种独立的应用层协议，而是 **HTTP + TLS**，用于加密 HTTP 通信。

HTTP/1.1 的消息可以直接以文本形式观察，非常适合用来理解 HTTP 的基本结构；HTTP/2、HTTP/3 对底层传输方式进行了优化，但 HTTP 的核心语义（方法、状态码、Header、Body 等）仍然保留。

### 7.2 请求（Request）

请求包含以下要素：

```Plain Text
HTTP Request

┌──────────────────────────────┐
│ Request Line                 │
│ Method + Path + Version      │
├──────────────────────────────┤
│ Headers                      │
├──────────────────────────────┤
│ Body（可选）                 │
└──────────────────────────────┘
```

![image.png](<图片和附件/image 8.png>)

- **请求行（Request Line）**：`方法 + 路径 + HTTP 版本`，例如 `GET /en-US/ HTTP/1.1`
- **方法（Method）**：要执行的操作，常见的有 GET、POST、PUT、PATCH、DELETE
- **路径（Path）**：URL 去掉协议、域名、端口后剩下的部分，例如 `/en-US/`
- **HTTP 协议版本（Version）**
- **标头（Headers）**：可选，用于向服务器传递附加信息
- **Body（主体）**：可选，包含发送的资源（如 POST 提交的表单或 JSON 数据）

常见方法对应的命令行示例：

```PowerShell
# GET
curl.exe https://httpbin.org/get

# POST
curl.exe -X POST https://httpbin.org/post

# PUT
curl.exe -X PUT https://httpbin.org/put

# PATCH
curl.exe -X PATCH https://httpbin.org/patch

# DELETE
curl.exe -X DELETE https://httpbin.org/delete
```

### 7.3 响应（Response）

响应包含以下要素：

![image.png](<图片和附件/image 9.png>)

- **HTTP 协议版本（Version）**
- **状态码（Status Code）**：表示服务器处理请求的结果，详见 [MDN 状态码参考](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Status)
- **状态消息（Status Message）**：对状态码的非权威性简短描述
- **标头（Headers）**：关于响应的附加信息，例如响应的位置或提供该响应的服务器信息
- **Body（主体）**：已获取资源的内容

#### 7.3.1 状态码分类

| 分类 | 含义       | 常见例子                           |
|------|------------|------------------------------------|
| 1xx  | 信息性响应 | 101 Switching Protocols            |
| 2xx  | 成功       | 200 OK、201 Created                |
| 3xx  | 重定向     | 301 永久移动、302 临时移动         |
| 4xx  | 客户端错误 | 400 Bad Request、404 Not Found     |
| 5xx  | 服务器错误 | 500 服务器内部错误、503 服务不可用 |

### 7.4 标头（Header）

Header（请求头 / 响应头）是 HTTP 消息中的**元数据**，用于描述请求或响应的附加信息。

#### 7.4.1 请求头（Request Headers）

包含有关要获取的资源或请求该资源的客户端的更多信息。

常见请求头：

- `Host`：目标主机（域名）
- `User-Agent`：客户端信息（浏览器、操作系统等）
- `Accept`：客户端可接受的响应内容类型
- `Content-Type`：请求 Body 的内容类型

#### 7.4.2 响应头（Response Headers）

包含有关响应的附加信息，例如响应的位置或提供该响应的服务器信息。

常见响应头：

- `Content-Type`：响应 Body 的内容类型
- `Content-Length`：响应 Body 的长度（字节数）
- `Set-Cookie`：要求客户端保存的 Cookie
- `Location`：重定向的目标地址

### 7.5 JSON

JSON（JavaScript Object Notation）是一种常见的**数据交换格式**。HTTP 接口通常用 JSON 作为请求/响应的 Body，配合 `Content-Type: application/json` 使用。

例如：

```JSON
{
    "name": "Den",
    "age": 19,
    "student": true,
    "skills": ["JSON", "Python", "HTTP"],
    "address": {
        "city": "Beijing",
        "country": "China"
    }
}
```

### 7.6 基于 HTTP 的 API

客户端可以通过各种工具或编程语言发起 HTTP 请求，例如：

- JavaScript：Fetch API
- Python：`requests`
- 命令行：`curl`
- 浏览器：地址栏 / DevTools

后端通常通过 HTTP API 向客户端提供服务。

### 7.7 请求与响应示例

HTTP 使用一组简单的方法（动词）表达操作，其中 GET 最常用。例如：

```HTTP
GET /en-US/ HTTP/1.1
Host: developer.mozilla.org
Accept: text/html
```

服务器发送的响应：

```HTTP
HTTP/1.1 200 OK
Content-Type: text/html
Content-Length: 45227

<!doctype html>
...
```

## 8. 实战：命令行

用三个命令就可以亲手验证前面讲的每一层——DNS 解析 → 网络连通性 → 应用层访问：

```Plain Text
nslookup github.com
        ↓
   DNS：域名 → IP

ping github.com
        ↓
   ICMP：测试网络连通性

curl.exe -I https://github.com
        ↓
   HTTPS：真正访问 Web 服务
```
