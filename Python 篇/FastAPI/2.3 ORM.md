# 2.3 ORM

[← 返回目录](<FastAPI.md>)

ORM（Object Relational Mapping，对象关系映射）：通过操作 **Python 对象**来操作数据库，避免直接编写 SQL 语句（SQL 基础见 [MySQL 笔记](<../../MySQL/MySQL.md>)）。

> 优势：
> 1. 减少重复的 SQL 语句
> 2. 代码简洁
> 3. 自动处理数据库连接和事务
> 4. 使用参数化查询，有效防止 SQL 注入

## 2.3.1 ORM 简介及安装

**ORM 与数据库的对应关系**

| 数据库 | Python 对象 |
| --- | --- |
| 表 | 模型类（继承 `Base`） |
| 字段 | 类属性（`mapped_column`） |
| 一行记录 | 模型类的实例对象 |
| 某列的值 | 实例属性 |

**SQLAlchemy** 是 Python 最常用的 ORM 框架，2.0 版本原生支持异步。配合 FastAPI 使用时，还需要安装对应数据库的异步驱动：

| 数据库 | 异步驱动 | 连接 URL 格式 |
| --- | --- | --- |
| MySQL | aiomysql | `mysql+aiomysql://用户名:密码@主机:端口/数据库名` |
| PostgreSQL | asyncpg | `postgresql+asyncpg://用户名:密码@主机:端口/数据库名` |
| SQLite | aiosqlite | `sqlite+aiosqlite:///./数据库文件` |

安装 MySQL 所需依赖：

```bash
pip install "sqlalchemy[asyncio]" aiomysql
```

> `sqlalchemy[asyncio]` 会额外安装 `greenlet`（异步执行必需），只安装 `sqlalchemy` 时创建异步引擎会报错。
>
> `aiomysql` 是 MySQL 的异步驱动，SQLAlchemy 通过它与 MySQL 通信。

**连接 URL 说明**（以 `mysql+aiomysql://root:123456@localhost:3306/fastapi_db` 为例）：

- `mysql+aiomysql`：数据库类型 + 异步驱动
- `root:123456`：用户名、密码
- `localhost:3306`：主机、端口
- `fastapi_db`：数据库名，需要提前创建（`create_all` 只建表，不建库；建库见 [MySQL 1.3 DDL](<../../MySQL/1.3 DDL.md>)）

## 2.3.2 建表

流程：**创建异步引擎 → 定义模型类 → 启动时建表**

> 本节及后续小节的代码是连续的，完整导入统一放在这里，后面只展示新增代码。

```python
from collections.abc import AsyncGenerator
from contextlib import asynccontextmanager
from datetime import datetime

from fastapi import Depends, FastAPI, HTTPException
from pydantic import BaseModel, ConfigDict
from sqlalchemy import DateTime, Float, String, and_, func, not_, or_, select
from sqlalchemy.ext.asyncio import AsyncSession, async_sessionmaker, create_async_engine
from sqlalchemy.orm import DeclarativeBase, Mapped, mapped_column

# 1. 创建异步引擎
ASYNC_DATABASE_URL = "mysql+aiomysql://root:123456@localhost:3306/fastapi_db"
async_engine = create_async_engine(
    ASYNC_DATABASE_URL,
    echo=True,       # 输出 SQL 日志，方便调试
    pool_size=10,    # 连接池中保持的持久连接数
    max_overflow=20  # 连接池中允许额外创建的连接数
)

# 2. 定义模型
class Base(DeclarativeBase):
    # 公共字段：所有继承 Base 的模型都会拥有
    create_time: Mapped[datetime] = mapped_column(
        DateTime, default=func.now(), comment="创建时间"
    )
    update_time: Mapped[datetime] = mapped_column(
        DateTime, default=func.now(), onupdate=func.now(), comment="修改时间"
    )

class Book(Base):
    __tablename__ = "book"

    id: Mapped[int] = mapped_column(primary_key=True, comment="书籍id")
    bookname: Mapped[str] = mapped_column(String(255), comment="书名")
    author: Mapped[str] = mapped_column(String(255), comment="作者")
    price: Mapped[float] = mapped_column(Float, comment="价格")

# 3. 启动时建表
async def create_tables():
    # 开启事务，执行建表
    async with async_engine.begin() as conn:
        await conn.run_sync(Base.metadata.create_all)

@asynccontextmanager
async def lifespan(app: FastAPI):
    await create_tables()
    yield

app = FastAPI(lifespan=lifespan)
```

**说明**

- `Mapped[类型]` + `mapped_column()`：SQLAlchemy 2.0 的声明式写法，类型注解对应数据库字段类型。
- `__tablename__`：指定表名；整型主键默认带 `AUTO_INCREMENT`（约束见 [MySQL 1.8 约束](<../../MySQL/1.8 约束.md>)）。
- `Base.metadata.create_all`：只创建**不存在**的表，已存在的表不会被修改；表结构变更需要使用 Alembic 迁移。
- `default=func.now()`：插入时自动填充创建时间；`onupdate=func.now()`：更新记录时自动刷新修改时间。
- `echo=True`：把生成的 SQL 打印到控制台，便于调试，生产环境建议关闭。
- FastAPI 0.93+ 已弃用 `@app.on_event("startup")`，推荐使用 `lifespan`（如上）；应用创建与运行见 [1.1 第一个 FastAPI 程序](<1.1 第一个 FastAPI 程序.md>)。

## 2.3.3 在路由中使用 ORM

核心：**创建会话工厂 → 用依赖项为每个请求提供会话 → 在路由中通过 [`Depends`](<2.2 依赖注入（自动注入）.md>) 注入会话**。

**1. 创建异步会话工厂**

引擎（engine）负责管理数据库连接，会话（session）负责执行具体的 ORM 操作。每个请求使用独立会话，请求结束后自动关闭。

```python
AsyncSessionLocal = async_sessionmaker(
    bind=async_engine,      # 绑定数据库引擎
    class_=AsyncSession,    # 指定会话类
    expire_on_commit=False  # commit 后对象属性不过期，避免异步下再次触发查询
)
```

> `class_` 带下划线，因为 `class` 是 Python 关键字，不能直接作为参数名。

**2. 依赖项：为每个请求提供会话**

```python
async def get_database() -> AsyncGenerator[AsyncSession, None]:
    async with AsyncSessionLocal() as session:
        yield session
```

- `yield` 前创建会话，请求处理完后退出 `async with`，会话自动关闭
- 不要在依赖项里自动 `commit()`：FastAPI 的 `yield` 依赖在响应发送后才执行清理，提交失败时客户端可能已经收到成功响应。写操作应在路由中显式提交（事务见 [MySQL 1.10 事务](<../../MySQL/1.10 事务.md>)）

**3. 定义响应模型**

FastAPI 的 `jsonable_encoder` 会自动跳过 SQLAlchemy 的内部属性（如 `_sa_instance_state`），所以直接返回模型对象也能序列化。但推荐用 `response_model` 明确返回字段、校验数据并生成接口文档（见 [1.3.2 响应模型](<1.3 响应.md#1-3-2>)）：

```python
class BookOut(BaseModel):
    model_config = ConfigDict(from_attributes=True)

    id: int
    bookname: str
    author: str
    price: float
```

> `from_attributes=True` 允许 Pydantic 从对象属性读取数据，而不是只接受字典。

会话工厂、依赖项和响应模型准备好后，在路由中通过 `Depends(get_database)` 注入会话即可，具体查询见 2.3.4。

## 2.3.4 查询数据

**1. 查询所有数据**

```python
@app.get("/books", response_model=list[BookOut])
async def get_books(db: AsyncSession = Depends(get_database)):
    result = await db.execute(select(Book))
    all_books = result.scalars().all()
    return all_books
```

- `db.execute(select(Book))`：执行查询，返回 `Result` 对象
- `result.scalars()`：取出每一行的模型对象
- `.all()`：返回列表

**2. 查询第一条数据**

```python
@app.get("/books/first")
async def get_first_book(db: AsyncSession = Depends(get_database)):
    result = await db.execute(select(Book))
    first_book = result.scalars().first()
    return first_book
```

- `.first()`：返回第一条记录，没有数据时返回 `None`
- `Result` 被 `.all()` 或 `.first()` 消费后不能再次使用，需要重新查询

**3. 按主键查询**

```python
@app.get("/book/{book_id}")
async def get_book(book_id: int, db: AsyncSession = Depends(get_database)):
    book = await db.get(Book, book_id)
    return book
```

- `db.get(Book, book_id)`：按主键查询单条记录，找不到返回 `None`
- `db.get(Book, 5)` 查的是 **id=5** 的那本书，不是前 5 本

## 2.3.5 条件查询

条件查询使用 `select(...).where(...)` 添加筛选条件。SQL 中对应的条件查询见 [MySQL 1.5 DQL](<../../MySQL/1.5 DQL.md>)（1.5.3–1.5.7）。

**1. 比较判断**

```python
@app.get("/book/equal/{book_id}")
async def get_book_by_id(book_id: int, db: AsyncSession = Depends(get_database)):
    result = await db.execute(select(Book).where(Book.id == book_id))
    book = result.scalar_one_or_none()
    return book
```

常用的比较运算：

| 运算 | 写法 |
| --- | --- |
| 等于 | `Book.id == 1` |
| 不等于 | `Book.id != 1` |
| 大于 / 小于 | `Book.price > 50` / `Book.price < 50` |
| 大于等于 / 小于等于 | `Book.price >= 50` / `Book.price <= 50` |

> `scalar_one_or_none()`：查询结果必须是一行或没有，返回单个对象；结果多于一行会报错。

**2. 模糊查询**

```python
@app.get("/book/search")
async def search_books(keyword: str, db: AsyncSession = Depends(get_database)):
    result = await db.execute(
        select(Book).where(Book.bookname.like(f"%{keyword}%"))
    )
    books = result.scalars().all()
    return books
```

- `%`：匹配任意多个字符；`_`：匹配单个字符
- 参数会作为绑定变量传入，不存在 SQL 注入问题

**3. 逻辑运算（与 / 或 / 非）**

```python
@app.get("/book/filter")
async def filter_books(keyword: str, db: AsyncSession = Depends(get_database)):
    result = await db.execute(
        select(Book).where(
            and_(
                Book.price < 100,
                or_(
                    Book.bookname.like(f"%{keyword}%"),
                    Book.author.like(f"%{keyword}%")
                )
            )
        )
    )
    books = result.scalars().all()
    return books
```

- `and_`：所有条件都满足
- `or_`：满足任意一个条件
- `not_`：取反，如 `not_(Book.price < 20)`

> 也可以用 `&`、`|`、`~`，但每个条件都要加括号，如 `(Book.price < 100) & (Book.author.like("余%"))`；条件多时用 `and_` / `or_` 更清晰。

**4. 包含（IN）**

```python
@app.get("/book/batch")
async def get_books_by_ids(db: AsyncSession = Depends(get_database)):
    id_list = [6, 7, 8]
    result = await db.execute(select(Book).where(Book.id.in_(id_list)))
    books = result.scalars().all()
    return books
```

- `in_([...])`：字段值在列表中
- 取反：`Book.id.not_in([6, 7, 8])`

## 2.3.6 聚合查询

聚合函数对多行数据计算并返回单个值，SQLAlchemy 中通过 `func.` 调用。SQL 中对应 1.5.10 聚合函数，见 [MySQL 1.5 DQL](<../../MySQL/1.5 DQL.md>)。

| 函数 | 作用 |
| --- | --- |
| `func.count(Book.id)` | 统计行数 |
| `func.max(Book.price)` | 最大值 |
| `func.min(Book.price)` | 最小值 |
| `func.sum(Book.price)` | 求和 |
| `func.avg(Book.price)` | 平均值 |

**1. 统计数量**

```python
@app.get("/book/count")
async def get_book_count(db: AsyncSession = Depends(get_database)):
    result = await db.execute(select(func.count(Book.id)))
    num = result.scalar()
    return num
```

- `select(func.count(Book.id))`：生成 `SELECT count(book.id) FROM book`
- 聚合查询只有一行一列，用 `result.scalar()` 取出

**2. 同时查询多个聚合值**

```python
@app.get("/book/statistics")
async def get_book_statistics(db: AsyncSession = Depends(get_database)):
    result = await db.execute(
        select(
            func.count(Book.id),
            func.min(Book.price),
            func.max(Book.price),
            func.avg(Book.price),
            func.sum(Book.price)
        )
    )
    count, min_price, max_price, avg_price, total_price = result.one()
    return {
        "count": count,
        "min_price": min_price,
        "max_price": max_price,
        "avg_price": avg_price,
        "total_price": total_price
    }
```

- `result.one()`：取出一行，按 `select()` 中的顺序解包
- 聚合结果不是模型对象，不能用 `scalars()`

## 2.3.7 分页查询

分页使用 `offset()` 和 `limit()`，SQL 中对应 1.5.13 分页查询，见 [MySQL 1.5 DQL](<../../MySQL/1.5 DQL.md>)：

- `offset(n)`：跳过前 n 条记录
- `limit(n)`：最多返回 n 条记录

公式：

```text
offset = (页码 - 1) × 每页数量
limit  = 每页数量
```

```python
@app.get("/book/get_books")
async def get_book_list(
    page: int = 1,
    page_size: int = 5,
    db: AsyncSession = Depends(get_database)
):
    skip = (page - 1) * page_size
    stmt = (
        select(Book)
        .order_by(Book.id)
        .offset(skip)
        .limit(page_size)
    )
    result = await db.execute(stmt)
    books = result.scalars().all()
    return books
```

- `page`、`page_size` 是查询参数（见 [1.2.2 查询参数](<1.2 路由.md#1-2-2>)），默认第 1 页、每页 5 条
- `.order_by(Book.id)`：分页时指定排序，避免每次查询顺序不同导致数据重复或遗漏
- 实际接口通常还需要返回总条数，可用 2.3.6 的 `func.count` 查询

## 2.3.8 新增数据

新增流程：**创建模型对象 → `add()` 加入会话 → `commit()` 提交**。SQL 中对应 INSERT / UPDATE / DELETE，见 [MySQL 1.4 DML](<../../MySQL/1.4 DML.md>)。

```python
class BookCreate(BaseModel):
    bookname: str
    author: str
    price: float


@app.post("/book/add_book", response_model=BookOut)
async def add_book(book: BookCreate, db: AsyncSession = Depends(get_database)):
    book_obj = Book(**book.model_dump())
    db.add(book_obj)
    await db.commit()
    return book_obj
```

- `BookCreate`：新增数据的请求模型（见 [1.2.3 请求体参数](<1.2 路由.md#1-2-3>)），不包含 `id`（主键由数据库自增生成）
- `@app.post`：新增资源，对应 HTTP 的 POST 方法（见 [网络基础 7.2](<../../网络基础/7. HTTP.md#7-2>)）
- `book.model_dump()`：把 Pydantic 对象转成字典，再展开传给 `Book(...)`
- `db.add()`：把对象加入会话，**不需要 await**
- `await db.commit()`：提交事务，写入数据库
- 返回 `book_obj` 并配合 `response_model=BookOut`，响应中会带上数据库生成的 `id`

## 2.3.9 更新数据（先查再改）

更新流程：**先查询对象 → 修改属性 → `commit()` 提交**。

```python
class BookUpdate(BaseModel):
    bookname: str
    author: str
    price: float


@app.put("/book/{book_id}", response_model=BookOut)
async def update_book(book_id: int, data: BookUpdate, db: AsyncSession = Depends(get_database)):
    # 1. 查询
    book = await db.get(Book, book_id)
    if book is None:
        raise HTTPException(status_code=404, detail="书籍不存在")

    # 2. 修改属性
    book.bookname = data.bookname
    book.author = data.author
    book.price = data.price

    # 3. 提交
    await db.commit()
    return book
```

- `db.get(Book, book_id)`：按主键查询，找不到返回 `None`
- 修改的是**同一个 ORM 对象**，SQLAlchemy 会自动跟踪属性变化
- `await db.commit()`：提交后更新才真正写入数据库
- 找不到记录时抛出 `HTTPException(404)`（见 [1.4 处理异常](<1.4 处理异常.md>)；`HTTPException` 已在 2.3.2 导入）

## 2.3.10 删除数据

删除流程：**先查询对象 → 删除 → `commit()` 提交**。

```python
@app.delete("/book/{book_id}")
async def delete_book(book_id: int, db: AsyncSession = Depends(get_database)):
    # 1. 查询
    book = await db.get(Book, book_id)
    if book is None:
        raise HTTPException(status_code=404, detail="书籍不存在")

    # 2. 删除
    await db.delete(book)

    # 3. 提交
    await db.commit()
    return {"message": "删除成功"}
```

- 删除不需要请求体，`book_id` 通过路径传入
- `await db.delete(book)`：把对象标记为删除
- `await db.commit()`：提交后才会真正从数据库删除
- 返回提示信息即可，不需要 `response_model`
