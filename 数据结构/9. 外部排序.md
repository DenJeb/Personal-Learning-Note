# 9. 外部排序 <a id="ch9"></a>

[← 返回目录](<数据结构（C语言）.md>)

数据太多，无法全部放入内存（考察读、写磁盘次数）。

## 9.1 外部排序步骤 <a id="9-1"></a>

1. 生成初始归并段（见[置换-选择排序](#9-4)）
2. 第一趟归并
3. 第二趟归并
4. 第三趟归并
5. ...直到归并为一段

**外部排序时间开销 = 读写外存时间 + 内部排序时间 + 内部归并时间**

**示例：10000 个记录，内存一次最多对 1000 个记录做内部排序**

1. 生成 10 个初始归并段（10000 / 1000）
2. 2 路归并：10 → 5 → 3 → 2 → 1，共 4 趟
3. 设数据块大小为 200 个记录，则处理一遍文件需访问外存 100 次（读 50 + 写 50）
4. 总外存访问次数 = 100（生成初始归并段）+ 4 × 100（4 趟归并）= **500 次**

## 9.2 优化：多路归并 <a id="9-2"></a>

多路归并（不是二路），归并树就是 k（k 路归并）叉树。

归并趟数 s = ⌈log(k, m)⌉（m 为初始归并段数）。k 越大趟数越少：上面的例子改用 5 路归并只需 2 趟，总外存访问次数 = 100 + 2 × 100 = **300 次**。

![多路归并趟数](<图片和附件/多路归并趟数.png>)

**多路归并负面影响：**

1. k 路归并需要开辟 k 个输入缓冲区，内存开销增加
2. 每挑选一个关键字需要对比关键字 (k - 1) 次，内部归并所需时间增加——可用[败者树](#9-3)优化

## 9.3 败者树 <a id="9-3"></a>

败者树——可视为一棵完全二叉树。k 个叶节点分别是当前参加比赛的元素，非叶节点用来记忆左右子树中的"失败者"，而让胜者往上继续比较，直到根节点。每选出一个最小关键字只需 ⌈log₂k⌉ 次比较。

## 9.4 置换-选择排序 <a id="9-4"></a>

用于生成**更长的初始归并段**（突破内存工作区大小的限制）。设输入文件 FI、输出文件 FO、内存工作区 WA 可容纳 w 个记录：

1. 从 FI 读入 w 个记录到 WA
2. 从 WA 中选出关键字最小的记录（MINIMAX），输出到 FO
3. 若 FI 不空，从 FI 读入下一个记录补入 WA
4. 从 WA 中选关键字大于刚输出的 MINIMAX 的最小者，作为新的 MINIMAX
5. 重复 3~4，直到 WA 中选不出比 MINIMAX 更大的记录——当前初始归并段结束，输出段结束标志
6. 重复 2~5，直到 WA 为空，得到全部初始归并段

结论：各初始归并段的**长度不等**。可用[败者树](#9-3)实现（段号小者优先胜出）。

![置换-选择排序](<图片和附件/置换选择排序.png>)

## 9.5 最佳归并树 <a id="9-5"></a>

各初始归并段长度不同时，按[哈夫曼树](<5. 树.md#5-8>)的思想组织归并顺序（权值 = 段长度），使总读磁盘次数最少。WPL = 总读磁盘次数，总读写次数 = 2 × WPL。

**示例：段长 9, 30, 12, 18, 3, 17, 2, 6, 24，3 路归并**

1. 简单两趟归并：总读写次数 = (9+30+12+18+3+17+2+6+24) × 2 × 2 = **484 次**
2. 最佳归并树（哈夫曼树）：[(3+2+6)×3 + (9+12+17+18+24)×2 + 30×1] × 2 = **446 次**

**虚段**：初始归并段数 m 不满足 (m - 1) % (k - 1) == 0 时，需补充长度为 0 的"虚段"补足（如 8 段做 3 路归并需补 1 个虚段）。
