# 2.4 视图、存储过程、触发器

[← 返回目录](<MySQL.md>)

## 2.4.1 视图介绍

> **视图（View）**：一种虚拟存在的表。视图中的数据并不在数据库中实际存储，行和列数据来自定义视图时查询所用的**基表**，在使用视图时动态生成。

- 视图只保存查询的 SQL 逻辑，不保存查询结果
- 对视图的查询，最终会转换为对基表的查询

## 2.4.2 视图基本语法

```sql
-- 创建视图
CREATE [OR REPLACE] VIEW 视图名称 [(列名列表)]
AS SELECT 语句
[WITH [CASCADED | LOCAL] CHECK OPTION];

-- 查看创建视图的语句
SHOW CREATE VIEW 视图名称;

-- 查询视图数据（与查表一样）
SELECT * FROM 视图名称;

-- 修改视图（两种方式）
CREATE OR REPLACE VIEW 视图名称 AS SELECT 语句;
ALTER VIEW 视图名称 AS SELECT 语句;

-- 删除视图
DROP VIEW [IF EXISTS] 视图名称 [, 视图名称] ...;
```

示例：

```sql
-- 只暴露研发部员工的 id、name、salary
CREATE VIEW vu_emp_dept1 AS
SELECT id, name, salary
FROM emp
WHERE dept_id = 1;

SELECT * FROM vu_emp_dept1;

SHOW CREATE VIEW vu_emp_dept1;

-- 修改视图定义
ALTER VIEW vu_emp_dept1 AS
SELECT id, name, salary, dept_id
FROM emp
WHERE dept_id = 1;

-- 删除视图
DROP VIEW IF EXISTS vu_emp_dept1;
```

## 2.4.3 检查选项

> **WITH CHECK OPTION**：对视图执行增删改时，检查数据是否满足视图的 `WHERE` 条件，不满足则拒绝操作。

```sql
-- 基表 users(id, username, age, status)
-- v1：成年用户
CREATE VIEW v1 AS
SELECT * FROM users WHERE age >= 18;

-- v2：基于 v1，只显示 30 岁以下
CREATE VIEW v2 AS
SELECT * FROM v1 WHERE age <= 30
WITH CASCADED CHECK OPTION;

-- age = 15：不满足 v1 的 age >= 18，被拒绝
INSERT INTO v2 (username, age) VALUES ('Mike', 15);

-- age = 35：满足 v1，但不满足 v2 自身条件，被拒绝
INSERT INTO v2 (username, age) VALUES ('Mike', 35);
```

两种检查方式：

| 选项     | 检查范围                                                                 |
| -------- | ------------------------------------------------------------------------ |
| CASCADED | 默认值。检查当前视图**以及所有依赖视图**的条件                           |
| LOCAL    | 检查当前视图的条件；只有当依赖视图也指定了检查选项时，才检查依赖视图的条件 |

```sql
-- 改为 LOCAL：v1 没有检查选项，插入 age = 15 只检查 v2 的 age <= 30，可通过
CREATE OR REPLACE VIEW v2 AS
SELECT * FROM v1 WHERE age <= 30
WITH LOCAL CHECK OPTION;

INSERT INTO v2 (username, age) VALUES ('Mike', 15);  -- 成功，但该行在 v1/v2 中不可见
```

## 2.4.4 视图更新

视图与基表是一一对应关系时（没有聚合、去重等），可以对视图执行 `INSERT` / `UPDATE` / `DELETE`，修改最终作用到基表上。

以下情况的视图**不可更新**：

1. 使用了聚合函数或窗口函数（`SUM`、`MIN`、`MAX`、`COUNT` 等）
2. 使用了 `DISTINCT`
3. 使用了 `GROUP BY`
4. 使用了 `HAVING`
5. 使用了 `UNION` 或 `UNION ALL`

> ⚠️ 不可更新的视图仍然可以查询；如果强行对这类视图执行 DML，MySQL 会报错。

## 2.4.5 视图作用

1. **简化查询**：把多表联查、子查询等复杂 SQL 封装成视图，使用时像查普通表一样简单
2. **安全**：视图可以只暴露部分行和列，可以把权限授予视图而不是基表，用户看不到敏感数据

```sql
-- 只开放 id、name 两列给该用户
CREATE VIEW vu_emp_public AS
SELECT id, name FROM emp;

GRANT SELECT ON vu_emp_public TO 'dev'@'localhost';
```

3. **数据独立**：视图可以屏蔽基表结构的部分变化（如基表新增列），只要视图定义不变，依赖视图的应用不需要修改

> 💡 视图本质是一条被保存的 SELECT 语句，合理使用可以简化开发，但不要嵌套过多视图，否则会带来额外的性能开销。

## 2.4.6 存储过程介绍

> **存储过程（Stored Procedure）**：事先经过编译并存储在数据库中的一段 SQL 语句的集合。

特点：

- 封装、复用：把一组 SQL 封装起来，需要时调用
- 可以接收参数、返回数据
- 减少应用与数据库之间的网络交互，提高效率

## 2.4.7 基本语法

```sql
-- 创建
CREATE PROCEDURE 存储过程名称 ([参数列表])
BEGIN
    -- SQL 语句
END;

-- 调用
CALL 存储过程名称([参数]);

-- 查看
SELECT * FROM information_schema.ROUTINES
WHERE ROUTINE_SCHEMA = 'test';

SHOW CREATE PROCEDURE 存储过程名称;

-- 删除
DROP PROCEDURE [IF EXISTS] 存储过程名称;
```

> ⚠️ 在命令行客户端中创建存储过程时，`BEGIN ... END` 内部的 `;` 会被误认为语句结束，需要先用 `DELIMITER` 修改结束符：

```sql
DELIMITER $$
CREATE PROCEDURE p1()
BEGIN
    SELECT COUNT(*) FROM emp;
END$$
DELIMITER ;
```

**参数模式**

| 模式  | 说明                                   |
| ----- | -------------------------------------- |
| IN    | 输入参数（默认），调用时传入值         |
| OUT   | 输出参数，调用时用用户变量接收结果     |
| INOUT | 既可以输入也可以输出                   |

```sql
CREATE PROCEDURE p_param(IN a INT, OUT b INT, INOUT c INT)
BEGIN
    SET b = a * 2;
    SET c = c + a;
END;

SET @b = 0, @c = 10;
CALL p_param(5, @b, @c);
SELECT @b, @c;   -- 10, 15
```

## 2.4.8 变量

**系统变量**：由 MySQL 服务器提供，分为 GLOBAL 和 SESSION 两级。

```sql
-- 查看
SHOW [GLOBAL | SESSION] VARIABLES LIKE 'auto_inc%';

-- 查询指定变量
SELECT @@global.autocommit;
SELECT @@session.autocommit;

-- 设置
SET @@session.autocommit = 0;
SET GLOBAL max_connections = 2000;
```

> 💡 不写 GLOBAL / SESSION 时默认是 SESSION。

**用户定义变量**：用户自己定义的变量，作用域为当前会话，不需要声明，直接用 `@变量名`。

```sql
SET @myname = 'Tom';
SET @myage := 18;

SELECT @myname, @myage;
```

**局部变量**：在存储过程 / 函数内部通过 `DECLARE` 声明，作用域为所在的 `BEGIN ... END` 块。

```sql
CREATE PROCEDURE p2()
BEGIN
    DECLARE myname VARCHAR(20) DEFAULT 'Tom';
    DECLARE myage INT DEFAULT 18;

    SET myname = 'Jack';
    SELECT myname, myage;
END;
```

> ⚠️ `DECLARE` 必须写在 `BEGIN ... END` 内的最前面，且要指定数据类型。

## 2.4.9 流程控制

**IF**

```sql
IF 条件1 THEN
    -- 语句
ELSEIF 条件2 THEN
    -- 语句
ELSE
    -- 语句
END IF;
```

示例：

```sql
CREATE PROCEDURE p_score(IN score INT)
BEGIN
    IF score >= 90 THEN
        SELECT '优秀';
    ELSEIF score >= 60 THEN
        SELECT '及格';
    ELSE
        SELECT '不及格';
    END IF;
END;
```

**CASE**（存储过程中的 CASE 语句，与查询里的 CASE 表达式不同）

```sql
-- 方式一：等值匹配
CASE 表达式
    WHEN 值1 THEN 语句1;
    WHEN 值2 THEN 语句2;
    ELSE 语句n;
END CASE;

-- 方式二：条件判断
CASE
    WHEN 条件1 THEN 语句1;
    WHEN 条件2 THEN 语句2;
    ELSE 语句n;
END CASE;
```

## 2.4.10 循环

**WHILE**：先判断条件，满足则执行

```sql
WHILE 条件 DO
    -- 语句
END WHILE;
```

**REPEAT**：先执行一次，再判断条件，满足则退出（直到型循环）

```sql
REPEAT
    -- 语句
UNTIL 条件
END REPEAT;
```

**LOOP**：死循环，需要配合 `LEAVE` 退出、`ITERATE` 跳过本次循环

```sql
[标签:] LOOP
    -- 语句
    IF 条件 THEN
        LEAVE 标签;
    END IF;
END LOOP [标签];
```

示例：计算 1 到 n 的和

```sql
CREATE PROCEDURE p_sum(IN n INT, OUT total INT)
BEGIN
    DECLARE i INT DEFAULT 1;
    SET total = 0;

    WHILE i <= n DO
        SET total = total + i;
        SET i = i + 1;
    END WHILE;
END;

CALL p_sum(100, @result);
SELECT @result;   -- 5050
```

## 2.4.11 游标

> **游标（Cursor）**：用来存储查询结果集的数据类型，可以在存储过程和函数中对结果集逐行处理。

使用步骤：

```sql
-- 1. 声明游标
DECLARE 游标名称 CURSOR FOR 查询语句;

-- 2. 打开游标
OPEN 游标名称;

-- 3. 获取一行记录到变量
FETCH 游标名称 INTO 变量1 [, 变量2 ...];

-- 4. 关闭游标
CLOSE 游标名称;
```

示例：逐行处理员工姓名

```sql
CREATE PROCEDURE p_cursor()
BEGIN
    DECLARE uname VARCHAR(20);
    DECLARE done INT DEFAULT 0;

    DECLARE u_cursor CURSOR FOR SELECT name FROM emp;
    DECLARE CONTINUE HANDLER FOR NOT FOUND SET done = 1;

    OPEN u_cursor;
    WHILE done = 0 DO
        FETCH u_cursor INTO uname;
        -- 处理 uname
    END WHILE;
    CLOSE u_cursor;
END;
```

## 2.4.12 条件处理程序

> **条件处理程序（Handler）**：定义在存储过程执行过程中遇到条件（错误、警告等）时的处理方式。

```sql
DECLARE handler_action HANDLER FOR condition_value [, condition_value]
    statement;

-- handler_action：CONTINUE（继续执行）| EXIT（退出当前块）| UNDO（回滚，MySQL 不支持）
-- condition_value：SQLSTATE 状态码 | SQLWARNING | NOT FOUND | SQLEXCEPTION | mysql 错误码
```

示例：

```sql
-- 捕获所有异常，回滚并退出
DECLARE EXIT HANDLER FOR SQLEXCEPTION
BEGIN
    ROLLBACK;
END;
```

> 💡 游标遍历时常用的 `DECLARE CONTINUE HANDLER FOR NOT FOUND SET done = 1;` 就是条件处理程序的典型用法。

## 2.4.13 存储函数

> **存储函数（Stored Function）**：有返回值的存储过程，参数只能是 `IN` 类型。

```sql
CREATE FUNCTION 函数名称(参数列表)
RETURNS 返回类型 [characteristic ...]
BEGIN
    -- 语句
    RETURN 值;
END;
```

示例：计算 1 到 n 的和

```sql
CREATE FUNCTION fun_sum(n INT)
RETURNS INT DETERMINISTIC
BEGIN
    DECLARE total INT DEFAULT 0;
    WHILE n > 0 DO
        SET total = total + n;
        SET n = n - 1;
    END WHILE;
    RETURN total;
END;

SELECT fun_sum(100);
```

> ⚠️ 开启二进制日志时，创建存储函数需要先设置：
>
> ```sql
> SET GLOBAL log_bin_trust_function_creators = 1;
> ```

## 2.4.14 触发器介绍

> **触发器（Trigger）**：与表有关的数据库对象，在 `INSERT`、`UPDATE`、`DELETE` 操作**之前或之后**，触发并执行触发器中定义的 SQL 语句集合。

作用：日志记录、数据校验、数据完整性约束等。

触发器的类型（6 种）：

| 时机   | 操作                        |
| ------ | --------------------------- |
| BEFORE | INSERT / UPDATE / DELETE    |
| AFTER  | INSERT / UPDATE / DELETE    |

> ⚠️ MySQL 只支持**行级触发器**（`FOR EACH ROW`），不支持语句级触发器。

## 2.4.15 触发器语法

```sql
-- 创建
CREATE TRIGGER 触发器名称
BEFORE | AFTER INSERT | UPDATE | DELETE
ON 表名 FOR EACH ROW
BEGIN
    -- SQL 语句
END;

-- 查看
SHOW TRIGGERS;

SELECT * FROM information_schema.TRIGGERS
WHERE TRIGGER_SCHEMA = 'test';

-- 删除
DROP TRIGGER [IF EXISTS] [数据库名.]触发器名称;
```

> 💡 `OLD` 表示操作前的数据，`NEW` 表示操作后的数据：
>
> | 操作   | OLD    | NEW    |
> | ------ | ------ | ------ |
> | INSERT | 不可用 | 可用   |
> | UPDATE | 可用   | 可用   |
> | DELETE | 可用   | 不可用 |

> ⚠️ 触发器内不能使用事务控制语句（`START TRANSACTION`、`COMMIT`、`ROLLBACK`），也不能返回结果集。

## 2.4.16 触发器案例

创建日志表：

```sql
CREATE TABLE emp_logs (
    id INT PRIMARY KEY AUTO_INCREMENT,
    operation VARCHAR(20) NOT NULL,
    operate_time DATETIME NOT NULL,
    operate_id INT NOT NULL,
    operate_params VARCHAR(500)
);
```

**INSERT 触发器**：插入员工后记录日志

```sql
DELIMITER $$
CREATE TRIGGER trg_emp_insert
AFTER INSERT ON emp
FOR EACH ROW
BEGIN
    INSERT INTO emp_logs (operation, operate_time, operate_id, operate_params)
    VALUES ('insert', NOW(), NEW.id,
            CONCAT('插入(id:', NEW.id, ', name:', NEW.name, ', salary:', NEW.salary, ')'));
END$$
DELIMITER ;
```

**UPDATE 触发器**：记录修改前后的值

```sql
DELIMITER $$
CREATE TRIGGER trg_emp_update
AFTER UPDATE ON emp
FOR EACH ROW
BEGIN
    INSERT INTO emp_logs (operation, operate_time, operate_id, operate_params)
    VALUES ('update', NOW(), NEW.id,
            CONCAT('修改前(name:', OLD.name, ', salary:', OLD.salary,
                   ') -> 修改后(name:', NEW.name, ', salary:', NEW.salary, ')'));
END$$
DELIMITER ;
```

**DELETE 触发器**：删除前记录日志

```sql
DELIMITER $$
CREATE TRIGGER trg_emp_delete
BEFORE DELETE ON emp
FOR EACH ROW
BEGIN
    INSERT INTO emp_logs (operation, operate_time, operate_id, operate_params)
    VALUES ('delete', NOW(), OLD.id,
            CONCAT('删除前(id:', OLD.id, ', name:', OLD.name, ', salary:', OLD.salary, ')'));
END$$
DELIMITER ;
```

> 💡 触发器执行失败时，触发它的原操作也会失败并回滚（InnoDB 支持事务），因此触发器中的逻辑要谨慎。
