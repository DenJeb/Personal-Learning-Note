# 2.5 锁

[← 返回目录](<MySQL.md>)

## 2.5.1 锁介绍

> **锁**：计算机协调多个进程或线程并发访问某一资源的机制。MySQL 中的锁用于管理对共享资源的并发访问，保证数据的一致性和有效性。

按锁的粒度分为三类：**全局锁**、**表级锁**、**行级锁**。

## 2.5.2 全局锁

> **全局锁**：锁定数据库中的所有表，加锁后整个库处于只读状态。

```sql
-- 加锁
FLUSH TABLES WITH READ LOCK;   -- 简称 FTWRL

-- 解锁
UNLOCK TABLES;
```

- 典型场景：全库逻辑备份
- 加锁期间，数据更新（DML）和表结构变更（DDL）都会被阻塞
- 缺点：主库备份时业务无法写入；从库备份时无法执行主库同步过来的 binlog

> 💡 InnoDB 支持事务，可以用 `mysqldump --single-transaction` 在备份时获取一致性快照，避免加全局锁。

## 2.5.3 表级锁

> **表级锁**：每次操作锁住整张表。锁定粒度大、冲突概率高、并发度低。MyISAM、InnoDB 都支持。

**表锁**

```sql
-- 加锁
LOCK TABLES 表名 READ;    -- 表共享读锁
LOCK TABLES 表名 WRITE;   -- 表独占写锁

-- 解锁
UNLOCK TABLES;
```

| 锁类型 | 其他会话读 | 其他会话写 | 当前会话 |
| ------ | ---------- | ---------- | -------- |
| read   | 允许       | 阻塞       | 只能读   |
| write  | 阻塞       | 阻塞       | 可读可写 |

**元数据锁（MDL）**

- MySQL 5.5 引入，访问表时自动加锁，无需手动操作
- 对表执行增删改查（DML）时加 MDL 读锁；修改表结构（DDL）时加 MDL 写锁
- 读锁之间兼容；读锁与写锁、写锁与写锁互斥

> ⚠️ 长事务持有 MDL 读锁时，DDL 会一直等待写锁；而 DDL 的写锁请求会阻塞后续的读锁请求，可能导致大量连接堆积。

**意向锁**

> **意向锁**：为了避免 DML 给表加表锁时逐行检查行锁，InnoDB 引入了意向锁。

- 意向共享锁（IS）：事务准备给某行加共享锁时，先给表加 IS 锁
- 意向排他锁（IX）：事务准备给某行加排他锁时，先给表加 IX 锁

|  | IS | IX | read 表锁 | write 表锁 |
| --- | --- | --- | --- | --- |
| IS | 兼容 | 兼容 | 兼容 | 互斥 |
| IX | 兼容 | 兼容 | 互斥 | 互斥 |

> 💡 意向锁之间互不冲突，只与表锁冲突。

## 2.5.4 行级锁

> **行级锁**：每次操作锁住对应的行数据。锁定粒度最小、冲突概率最低、并发度最高。仅 InnoDB 支持。

三种行锁：

| 类型 | 说明 |
| ---- | ---- |
| 记录锁（Record Lock） | 锁定单条索引记录 |
| 间隙锁（Gap Lock） | 锁定索引记录之间的间隙（不含记录本身），阻止其他事务插入；在可重复读隔离级别下生效 |
| 临键锁（Next-Key Lock） | 记录锁 + 间隙锁，锁定记录及其前面的间隙（左开右闭） |

**共享锁与排他锁**

```sql
-- 共享锁（S）：多个事务可以同时持有
SELECT * FROM emp WHERE id = 1 FOR SHARE;
-- MySQL 8.0 之前写作：SELECT ... LOCK IN SHARE MODE;

-- 排他锁（X）：只允许一个事务持有
SELECT * FROM emp WHERE id = 1 FOR UPDATE;
```

- `INSERT`、`UPDATE`、`DELETE` 会自动加排他锁
- 共享锁与共享锁兼容，共享锁与排他锁、排他锁与排他锁互斥

> ⚠️ InnoDB 的行锁是**基于索引实现**的。如果查询条件没有用到索引，InnoDB 会扫描全表并对所有行加锁，效果等同于表锁。
>
> ```sql
> -- id 有索引：只锁 id = 1 这一行
> SELECT * FROM emp WHERE id = 1 FOR UPDATE;
>
> -- name 无索引：扫描全表，所有行被锁
> SELECT * FROM emp WHERE name = 'Tom' FOR UPDATE;
> ```

**隔离级别与行锁**

- `READ COMMITTED`：大多数场景下使用记录锁
- `REPEATABLE READ`（默认）：使用临键锁，避免幻读
